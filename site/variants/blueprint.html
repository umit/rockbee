Compute moves.

Rockbee separates the work of a database from the objects it persists. One writer. Independent readers. A durable dataset they share.

01 / The architectural choice

More reader compute.
The same durable dataset.

A new reader works against shared objects. It does not need its own full independent durable replica of the dataset. Reader processes still have their own caches, memory needs, and catch-up work.

ASeparate lifecycles.

Keep persisted storage apart from individual reader processes. Add reader compute according to your workload without making a full new durable copy for each reader.

BTwo deliberate read paths.

Point GETs use SlateDB. SQL runs in reader-side DuckDB over background-published Parquet. Reader visibility and SQL publication are eventual.

02 / The working interface

A small surface.
Room for real data.

Use opaque byte keys and values, or schema-free JSON objects. The Rust SDK supports generated UUIDs, caller-owned IDs, optional TTL, point lookups, deletion, and actual DuckDB SELECTs.

use rockbee_client::RockBeeClient;
use serde_json::json;

let client = RockBeeClient::connect(&gateway).await?;
let products = client.table("products");
let write = products.put(&json!({"name": "Keyboard"}));
println!("{}", write.id()); // UUID is already available.
let id = write.await?;     // Wait for durable ACK.

products.put_key("sku-42", &json!({"name": "Keyboard"}), None).await?;
let document = products.get("sku-42").await?;
products.delete(&id).await?;

03 / Operating assumptions

The contract is part of the design.

01

Acknowledge durability.

A successful PUT or DELETE waits for SlateDB’s durable acknowledgement. Eager completion handles keep submission separate from waiting.

02

Allow for catch-up.

A reader can lag the writer. SQL can lag a point GET while the background exporter publishes its Parquet projection. Query results include the exported WAL watermark.

03

Make uncertainty explicit.

A lost mutation acknowledgement can leave an unknown outcome. Rockbee does not automatically replay uncertain mutations.
