02 — The Rust interface

Write an object.
Ask a question.

One RockBeeClient. A table handle. No schema ceremony. Use JSON when it fits and raw bytes when you need your own format.

GET visibility and SQL publication are eventual. The result’s exported WAL watermark makes the SQL projection explicit.

Read the complete example ↗
use rockbee_client::RockBeeClient;
use serde_json::json;

let client = RockBeeClient::connect(&gateway).await?;
let products = client.table("products");

let write = products.put(&json!({
    "name": "Keyboard", "price": 99.5
}));
println!("{}", write.id()); // UUID, before await.
let id = write.await?;   // Durable ACK.

// Or keep an ID from your application.
products.put_key("sku-42", &json!({
    "name": "Keyboard"
}), None).await?;
let result = products.query(
    "SELECT id, value->>'name' AS name
     FROM products
     ORDER BY id
     LIMIT 20"
).await?;

println!("WAL {}", result.exported_wal_file_id);
println!("{:?}", result.rows);

// SQL reads published Parquet, not a fresh KV scan.
// Poll when you need to observe a recent write.
{
  "rows": [
    {
      "id": "sku-42",
      "name": "Keyboard"
    }
  ],
  "exported_wal_file_id": 128
}

// Illustrative output from a published generation.
// The watermark is not a read-after-write guarantee.

Separate compute.
Shared storage.

A single writer and independent readers share one durable object store. Add reader compute without a full independent dataset replica for every reader.

Persisted data stays in shared object storage, apart from reader process lifecycles. Each reader manages its own SlateDB caches and catch-up.

03 — The contract

Know what
success means.

01

Acknowledge
durability.

A successful PUT or DELETE waits for the durable storage acknowledgement. Eager completion handles let you submit work immediately and await its outcome.

02

Expect
catch-up.

Readers can lag the writer. SQL can lag a reader GET while Parquet exports catch up. TTL applies to documents and raw values; an ACK is not immediate reader visibility.

03

Keep uncertainty
explicit.

A lost mutation acknowledgement can leave an unknown outcome. Rockbee does not automatically replay uncertain mutations. Recovery stays an application decision.

A pilot you can inspect. Evaluate against your own workload, consistency needs, and operational requirements.

No promised throughput. No hidden consistency shortcut.
Source, examples, and tests are there to read.
