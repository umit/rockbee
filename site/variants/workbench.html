01 / Disaggregated architecture

Separate compute.
Share the durable data.

Rockbee separates compute from storage. A single writer and independent readers work against the same durable object store, with the gateway routing each request to its service.

⌘GatewayClient entry point
→
Single writerDurable mutations
ReadersGET + DuckDB SQL
↔
▱Object storeSlateDB / S3
PUT / DELETE → gateway → single writer → SlateDB → durable acknowledgement

Add compute, reuse the data.

Add reader processes without a full independent dataset replica per reader. Each reader keeps its own caches and catches up with shared storage.

Persist beyond a process.

Durable data lives in shared object storage such as S3, separate from reader lifecycles. Reader compute and persisted storage have distinct responsibilities.

Choose the read path.

Point GETs use SlateDB. SQL uses DuckDB over background-published Parquet. Reader visibility and the SQL projection are both eventual.

02 / A small SDK surface

Your IDs.
Your documents.
Your questions.

RockBeeClient connects to the gateway. A table is a namespace for JSON objects with flexible fields. Use raw PUT, GET, and DELETE on the same client for opaque bytes.

The table write starts eagerly. Its generated UUID is available before you await the durable result. Use put_key to keep IDs from your application, and optional TTL to expire a document.

03 / Explicit, by design

Know what your
data layer promises.

Storage decisions become application behavior. Rockbee keeps durability, visibility, and uncertain outcomes separate so you can make those decisions deliberately.

DURABILITY

Acknowledged means durable.

PUT and DELETE wait for SlateDB’s durable acknowledgement. The gateway adds no separate key/value cache.

VISIBILITY

Catch-up is part of the model.

Readers may lag writes. SQL can lag GET while the background exporter publishes Parquet. Query results include an exported WAL watermark.

UNCERTAINTY

No automatic mutation replay.

A lost acknowledgement can leave an unknown outcome. Rockbee surfaces that uncertainty; your application decides how to recover.

Put your workload on the bench.

Rockbee is an open-source pilot. Run the separate writer, reader, and gateway locally. Inspect the implementation, then evaluate the behavior you need.
