# TTL plan review

Status: final revised plan APPROVED for specification and predesign quality. This review authorizes no implementation, dependencies or production changes. Advisor directly discussed and resolved the concrete findings with planner, verifier and root, then reread the final plan. No unresolved design disagreement requires a Judge.

```text
eager TTL PUT -> one replicated expiry timestamp -> atomic value/metadata/index
leader observes due -> ExpireIfMatch(version, expiry) -> committed absence
```

## Accepted approach

The leader assigns one absolute expiry timestamp immediately before submitting the TTL-bearing command; followers never recompute it from local clocks. All replicas apply the same value, version and expiry. Strong GET uses a real authority barrier and coherent state view. If the current version is due, GET submits conditional expiration and re-reads after committed application; no local read filter fabricates absence. A stale expiry cannot delete a replacement because its full version identity and expected deadline must match. Ordinary PUT clears TTL, DELETE removes its metadata/index, and logical deletion precedes ordinary RocksDB physical reclamation.

This makes expiration a replicated state transition. Once that version's expiration is committed, slower clocks, restart and leader changes cannot resurrect it. No durable observed-time floor or monotonic-wall-clock wrapper is necessary for this property. A backward wall-clock step may delay expiration, which the contract already permits.

## Initial review corrections, now resolved in the plan

1. **Clock contract.** Instantaneous pairwise skew is insufficient to promise a real elapsed minimum: all nodes can jump forward together, retaining zero pairwise skew, and expire immediately. Root selected an explicit operator assumption `|C_node(t) - UTC(t)| <= epsilon` at issuance and expiry observation. Proposed immutable `max_absolute_clock_error_ms` defaults to 1000, valid 1..60000. Due means exactly `now >= issued_at + ttl + 2*epsilon`, with all additions/multiplication checked before admission. This is conditional at-least-TTL semantics, not evidence that runtime clocks satisfy the assumption; violating it can cause early irreversible expiry. Remove language suggesting `now + allowance >= expiry`. Remove the durable floor and its StateRecord/snapshot fields; preserve the current StateRecord encoding.
2. **Outcome ownership.** GET-triggered expiry can commit after the caller's deadline. An uncertain internal result produces a read failure or a bounded fresh authoritative reconciliation within the original deadline, never fabricated None. Keep the proposal and permits owned until actual completion. Scheduler retries are fresh state-based conditional work; they do not relax public mutation no-replay. A no-op expiry must advance applied progress normally. Validate the replicated observation/deadline relationship deterministically, without a clock call in apply.
3. **Compatibility and legacy identity.** Preserve every existing Command/ApplyResult tag, including Applied at zero and any Metadata variants added before TTL. Append variants rather than replacing the enum. Legacy records require `Option<LogId>` or an explicit Legacy representation. Choose an explicit old-format/legacy marker or bounded format migration: missing TTL metadata cannot simultaneously mean legitimate legacy data and detected corruption. Never claim `serde(default)` alone makes old postcard StateRecord tuples decode after adding fields. Specify v1 snapshot import, new-format publication, interrupted migration/reopen and repeated equal-progress install behavior.
4. **All generation-owned state.** Current snapshot/GC/recovery code handles the data prefix. TTL's record and expiry prefixes must participate in generation allocation checks, obsolete-generation cleanup and startup validation. Capture raw value and record metadata from the same MVCC snapshot. V2 logical records preserve full version/expiry and rebuild a bounded index while importing into an invisible generation; activation remains atomic after complete validation. Same-progress validation compares logical TTL metadata as well as bytes. Validate correspondence between raw rows, required record metadata and index entries; do not silently make a TTL value immortal when metadata is missing.
5. **Apply and scheduler bounds.** Charge emitted metadata, old-index deletion and new-index insertion as well as raw value and StateRecord; existing input-entry size accounting alone does not bound expanded WriteBatch output. Same-key commands in one apply chunk must see earlier effects. Bound retained candidate bytes and proposal count process-wide across hosted groups, not only per group; include work surviving a timeout. Reads must not wait behind an unbounded sweep backlog. A bounded fresh scan remains a hint; the replicated conditional check is authoritative.
6. **Avoid speculative cleanup machinery.** Normal RocksDB compaction already reclaims obsolete physical records after committed deletion. Remove the proposed manual-compaction coordinator, its queue/defaults and mandatory tests from the first TTL milestone. Revisit only after disk measurements identify a need. No compaction filter may independently change logical visibility.
7. **Duration precision.** Explicitly reject fractional milliseconds or round them upward with checked arithmetic; silently truncating a requested duration contradicts at-least-TTL semantics. Validate `expires_at - issued_at` lies within the permitted TTL range, and check the added clock margin at proposal admission. Keep minimum/maximum boundary tests meaningful.

## Focused final plan gates

Use controlled clocks for the absolute-bound endpoints, backward steps, leader replacement and a shared forward jump beyond the assumption. Distinguish the conditional time guarantee from unconditional no-resurrection after committed deletion. Exercise renewal followed by an old expiry, ordinary overwrite clearing TTL, delete/expiry ordering, and both command orders within one apply iterable/chunk. Verify uncertain expiry reads, no quorum and dropped callers without false absence or leaked permits.

Require one complete legacy-to-TTL upgrade/reopen/snapshot path, expired-value snapshot transfer, concurrent renewal during snapshot capture, corrupt/missing metadata handling, partial inactive-generation recovery and cleanup of all new prefixes. Large due sets must demonstrate bounded retained work and unrelated-group progress. These are plan requirements, not claims of completed tests. Broader churn and TTL soak stay behind the currently prioritized stable three-node soak and communication fixes.

## Separate writer-lifecycle finding

The revised server regression observes EOF on the same TCP connection while input remains active, then sends a unique late request ID. Its red result is valid evidence of admission after response-writer termination. The minimal writer-JoinHandle completion branch is approved; it must retire intake and retain accepted handler ownership. Advisor requested a completion counter after each held handler is released, with completed equal to admitted after shutdown, so an abort-all implementation cannot falsely satisfy the drain claim. Production fix verification remains the worker/verifier's next step.

## Final clause review

The final plan states the absolute UTC-error assumption and exact checked `2*epsilon` predicate, removes the durable clock floor and manual compaction, preserves StateRecord/StorageIdentity encodings, and stores immutable epsilon through replicated `RBRTTLC1` initialization. Startup first makes metadata group zero available for that read; only data groups undergo bounded migration before their Raft/public TTL admission starts. Group zero stays on raw snapshots and rejects TTL auxiliary state. Descriptor and image decoders dispatch strictly between RBRDESC1/RBRSNAP1 and their v2 counterparts.

Migration publishes the V2 marker and deletes its journal in one synchronous batch. Missing-marker recovery cannot overwrite real expiring metadata as legacy. All five generation-owned tags participate in recovery/GC, with the declared process-wide candidate/proposal admission and expanded batch accounting.

The final review additionally caught a canonical-replay issue: a caught-up replica's migrated old PUT must match another replica importing an older v1 snapshot and replaying that same PUT. The adopted simpler rule is explicit `NonExpiring(None, None)` metadata for **all** ordinary/legacy PUTs; only TTL PUTs carry `Expiring(Some(LogId), Some(expiry))`. This avoids adding a second ordinary-PUT command. It still invalidates every old conditional expiry after an ordinary overwrite, and metadata presence remains mandatory in V2. The plan now requires a same-applied-LogId comparison regression for those two recovery paths.

No concrete plan blocker remains. Implementation, runtime proof of the stated gates, and any performance conclusions remain pending and require their own review; the clock-error bound remains an operator assumption rather than an observed guarantee.
